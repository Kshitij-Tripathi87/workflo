| 3 | **Cortex Autopilot** (DataHub impact gate) and **Tenant Shield** naming | `backend/`, `frontend/`, `action/`, `examples/`, `ci-templates/` | **Adjacent product.** Not part of the Workflo QA brief; do not grow. `apps/control-plane` (the Workflo control plane) currently carries the "Tenant Shield" name in code |

**The single largest gap against the brief:** no Firecracker/KVM/vsock/jailer/microVM code, dependency, or documentation exists anywhere in the tree (verified by case-insensitive full-tree search; the only `kvm` hits are base64 substrings in lockfile integrity hashes). The current execution boundary is Docker (`apps/sandbox-executor`, documented "Phase 1 default") or bwrap+namespaces (`packages/sandbox-runtime`, the Linux-gated path). Neither is the microVM boundary the brief mandates (ADR-001), and **no fallback may be relabeled as equivalent**.

**Second largest gap:** no durable orchestration. `POST /v1/runs` executes via in-process `asyncio.create_task` (`apps/control-plane/app/api/v1/runs.py:207`), with an unused Redis/Celery-shaped queue stub. This is not a production foundation for the run lifecycle (§8 of the brief).

**Also absent:** admission/policy-bundle enforcement (the token `ADMITTED` appears nowhere in the tree), receipt v5 (DSSE-style, externally validated, externally signed), the four-way finding classification as a persisted model, and the entire patch/remediation protocol.

## 5. Canonical-tree decision (Phase 0 deliverable)

**Proposal (ADR-0001): Python-first product contracts; adopt the TypeScript layer's SQL and ledger discipline; keep TS runtime code frozen, not extended.**

Rationale:

1. The brief's target stack (ADR-014: Next.js + FastAPI + PostgreSQL) and target layout (`apps/control-plane`, `orchestrator/`, `worker/`, `evidence-service/`, `guest-runtime/`) are satisfied by the Python lineage, which is also the shipping product (CLI v1.1.1, 123+119+400+ tests green, proof-bundle acceptance at `bdf686e`).
2. The microVM mandate (ADR-001) replaces **both** current execution boundaries. Neither the Docker executor nor the bwrap runtime survives as the production boundary, so their language split is moot; new host/guest code should follow the brief's Python worker layout.
3. `packages/db` migrations are SQL — directly adoptable into the canonical PostgreSQL schema regardless of application language, and they already encode RLS, tenant scope, an append-only ledger, and a DB-enforced transition graph (the strongest data-integrity assets in the tree).
4. The canonical evidence/event byte format must be **one** format (see §6.2). The TS canonical-JSON chain is the better base; it is adopted as the canonical profile and the Python ledger is versioned forward (legacy receipts v1–v4 keep verifying under their original format).

Consequences:

- `packages/workflo-schema` becomes the single authored home of the frozen contracts (v1), exported to language-neutral JSON Schema for the web layer; `packages/contracts` (Zod) becomes a validated mirror for `apps/web` (not a second authority).
- `packages/sandbox`, `packages/ingestor`, `packages/executor` remain in the tree and CI (they are not harmed by this decision) but receive no new capability investment; they are superseded by the Firecracker worker path. Retire only after Gate B passes.
- `backend/` + `frontend/` (Cortex Autopilot) stay frozen as an adjacent product; no brief work targets them.

*Open for ratification by the project owner; recorded as ADR-0001 with alternatives.*

## 11. Addendum — Phase 3 status (2026-11-11, same day)

**Phase 3 — MicroVM worker foundation: implemented (`worker/` package, Phase 3.0 of the Gate B path).**

- `workflo_worker_host.assignment` — versioned, digest-bound `SandboxAssignmentV1` (per brief §3.2): run/attempt/sandbox identity, policy + runtime digests, digest-pinned guest kernel/rootfs, resource ceilings, default-deny network policy, capabilities, authenticity hook (worker refuses unsigned assignments in production).
- `workflo_worker_host.admission` — honest host probing (`/dev/kvm` device + rw access, pinned Firecracker/jailer version match, image allowlist, capacity, health) and `check_eligibility`: **every gap is a blocker; no fallback is ever named** (missing KVM → ineligible, full stop).
- `workflo_worker_host.protocol` — the narrow guest/host message layer (brief §3.4): frozen 7-type registry, strict schemas, attempt/sandbox binding, protocol-version negotiation, strictly sequential sequences (gaps AND replays rejected), payload digests, 1 MiB frame cap, unknown operations rejected. Transport seam keeps real vsock Linux-gated.
- `workflo_worker_host.network` — per-run nftables ruleset generation: default-deny posture, always-blocked set (cloud metadata, link-local, RFC1918, CGNAT, multicast), IP-literal-only allowlist (control plane resolves hostnames), fail-closed application semantics (unapplicable rules = no egress, never open egress).
- `workflo_worker_host.manager` — typed host operations only (`provision_sandbox`, `get_sandbox_status`, `request_graceful_shutdown`, `force_terminate`, `collect_host_lifecycle_evidence`, `verify_resources_removed`, `destroy_sandbox`). **No `execute_command` exists.** Fail-closed provisioning order: assignment authenticity → worker eligibility → egress enforcement → fresh per-run scratch disk → VMM start → guest-identity verification before READY. Guest-ready timeout → force-terminate + independent teardown verification.
- Teardown: 8 canonical checks (ADR-0018 receipt v5 shape) with injected probes; unperformable check = failure; outcome mapping VERIFIED_CLEAN / VERIFICATION_FAILED / UNKNOWN feeding the trust outcome.
- Tests: 60 unit tests green on any platform; `worker/tests/integration/test_kvm_boot.py` seeds Gate B and skips with explicit reasons off Linux/KVM ("a skip is a documented non-proof, never a pass").

**Gate B status (honest): NOT YET PROVEN.** What exists is the complete host-side contract, protocol, and enforcement logic with negative tests. What Gate B additionally requires and does not yet exist: the pinned release artifacts (Firecracker/jailer binaries, guest kernel, rootfs image with digests), the real vsock transport wiring, the in-guest supervisor, cgroups/netns/sockets/capabilities teardown probes, and a real boot on a KVM host with retained evidence.
